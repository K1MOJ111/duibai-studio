# 对白 · 台词打磨工作台

**当前状态：已上线，已完成线上真实 API 与浏览器关键路径验证（2026-09-11）。**

在线体验：[duibai-studio.vercel.app](https://duibai-studio.vercel.app)，体验码由候选人私下提供。

公开源码：[K1MOJ111/duibai-studio](https://github.com/K1MOJ111/duibai-studio)。

给短剧编剧的一场台词精修工具。把完整场景贴进来，获得建议稿，对照后决定采用，继续编辑并导出 TXT。

解决的是台词中的书面解释、总结腔和不自然的接话。剧情没有看点、结构改编和整部剧生成不在本版范围内。模型建议可能遗漏人物诉求或新增细节，因此保留原稿、完整场景对读及按句采用；不宣称自动保证语义一致或达到此前 Codex 人工协作改稿的质量。

## 本地运行

需要 Node.js 24，无第三方运行依赖，无需数据库。

1. 将 `.env.example` 复制为 `.env`，填入官方 DeepSeek 的 `DEEPSEEK_API_KEY`。
2. 执行 `npm start`，打开 `http://127.0.0.1:3030`。
3. 执行 `npm test` 检查输入边界、原文保护、局部替换、采用合并、模型响应、访问控制及失败后的并发锁释放。测试使用明确的模拟响应，不调用真实 API。

`.env` 被 Git 忽略。已有配置文件也可通过本地环境变量 `DEEPSEEK_KEY_FILE` 指定，程序只读取其中的 DeepSeek 密钥，不写入副本。本地只监听回环地址。

若系统占用了 3030 端口，可在 PowerShell 中先执行 `$env:PORT='13030'` 再运行 `npm start`，访问相应端口。

## 怎么体验

1. 点击“试试示例”，或粘贴 / 导入自己的 UTF-8 TXT。示例是“父亲的夜校作业”原创场景，只填入原稿，**不会载入缓存改稿**。
2. 点击“开始打磨”，服务端真实调用 DeepSeek。背景选填，已有信息不必重复填写。
3. 阅读修改对照；需要时展开“连读完整场景”。所有建议默认选中，可以取消个别建议或全部保留原句。
4. 采用后在完整正文中继续编辑，再复制或导出。导出内容来自当前编辑框。撤销采用恢复采用前的一份正文。

每次上限 5,000 字、80 句台词。对白格式为单行 `角色：台词` 或 `角色: 台词`，支持角色名后的括号提示；动作单独成行，建议使用 `△`。界面显示识别的对白数量和人物。换行统一为 LF，导出为带 BOM 的 UTF-8 TXT。页面没有自动保存，离开前需要导出。

## AI 如何工作，以及实现取舍

- `rewrite-prompt.txt` 先要求理解人物在对谁说、想争取什么，再把书面表达打磨成当场回应。模型只输出“行号、原句、建议、修改说明”，程序逐条核对原句后替换；没有建议的行直接来自用户原稿。
- 使用官方 `deepseek-v4-pro`，high 思考强度，每次最多 8,192 输出 tokens。早期 Flash 整场重写及自动审核方案出现原意偏移，后来改用 Pro 直接生成局部建议；这同时调整了模型、提示词和输出形式，不能把改善单独归因于某一项。
- 程序校验输出完整、原文引用、行号唯一、说话人前缀与非对白行不变。另有保守字面保护：原句中的“不一定、未必、不是一定”被建议删掉时，保留原句并告知用户。它可能错过同义改法，也不能识别所有语义变化。
- 六段原创小样中，五段有局部表达改善，一段自然对白原样保留；其中裁缝场景有一条建议使否定语气更绝对，被上述规则保留为原句。全部模型原始建议与输入在 `evaluation.json`，不能当成独立用户验证或通用成功率。
- 前端用原生 HTML/CSS/JavaScript，后端用 Node.js 标准库和原生 fetch；没有引入 Agent 框架、RAG、数据库或自动多轮自评。
- 后端 120 秒模型超时，不自动重试；失败保留原稿和已有改稿。模型调用期间锁定编辑，并显示实际等待秒数。已测小样约 15—74 秒，更长输入可能超时或输出截断。

开发中使用 Codex读取历史方法、拆解范围、实现、运行检查和真实浏览器验证；识别到错误后保留失败样本再调整实现。质量结论来自实际输入输出，不以模型自评代替验收。

## 部署准备

Vercel 已实际部署：静态文件在 `public/`，模型代理在 `api/optimize.js`，函数最长 180 秒。`.vercelignore` 仅允许上传运行所需源码与配置，排除本地录屏、调试产物和环境文件。线上匿名访问、体验码校验和一次真实改稿均已通过检查。

当前通过 Vercel CLI 发布，尚未绑定 GitHub 自动部署；后续代码修改需执行 `npx vercel deploy --prod` 发布。GitHub 推送本身不会更新线上产品。

在 Vercel 导入本仓库，使用 Node.js 24、Other 框架、`public` 输出目录。设置服务端环境变量：

- `DEEPSEEK_API_KEY`：真实模型密钥，通过平台环境变量界面或 CLI 标准输入配置，禁止写入仓库。
- `DEMO_ACCESS_CODE`：至少 12 个字符的随机体验码，私下提供给评审。

线上缺少有效体验码时拒绝调用模型。不要将体验码当作多用户账户系统；它只供有限评审分享。本版只有单进程并发保护，不保证多个云实例之间的全局次数或费用上限。若开放公众使用，优先补共享配额控制。没有服务端剧本数据库、内容日志或自动备份；模型服务提供者会收到用户主动提交的文本。

参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Vercel Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js)。

## 文件

`public/`：界面和共享文本校验；`api/optimize.js`：模型请求与服务端边界；`local.mjs`：本地入口；`rewrite-prompt.txt`：当前修改方法；`test.mjs`：离线检查；`evaluation.json`：六次模型输入、原始建议、用量与耗时。真实验证结果和当前边界见 `VALIDATION.md`。本地调试产物在被忽略的 `output/` 中。

## 产品选择与下一步

目标用户是已有剧本初稿、需要调整人物口语和当场情绪的短剧编剧。输入已有场景，直接得到定位明确的建议与说明，再采用、编辑、导出，减少反复描述修改位置和手工拼接正文的步骤。这个价值假设尚未通过真实编剧试用证明。

本版聚焦可审阅的台词修改，不承诺零 AI 味或自动保证原意，不处理剧情看点、整剧结构、DOCX 排版、账户与多人协作。没有 RAG、数据库、模型自评分或后台自动循环改稿。优先改进是用真实授权剧本验证采用率与剩余手改量，并缩短长场景等待时间。
